# libresprite-parts-editor

heosterra の部位のフォルダ（`〇〇-parts`。例: `docs/art/canon/character/girl/a-pose/s-parts`）を、**部位ごとのレイヤーに分けて LibreSprite で直し、部位ごとの PNG へ書き戻す**ための道具です。

- `〇〇-parts` のフォルダを渡すと、中の `parts.json` を読み、**部位ごとに 1 枚のレイヤー**にして読み込みます。部位を、隠れた所まで含めた 1 枚の絵として直せます。
- 読み込んだ直後は、json の `order` の順に奥 → 手前へ部位のレイヤーが並び、全部の部位を重ねた絵になります。
- 部位ごとに、ほかの部位に隠れた所も含めた形の外側の輪が **ガイド** として出ます（隠れた所に接する所は点線）。ガイドと `map.png` のレイヤーは一番下にあり、部位の絵には被りません。
- 書き戻すと、画素の変わったファイルだけを書き換えます。直していないファイルはバイト列まで変わりません。
- フォルダに `joints-drawn.json`（絵の上の関節の位置）があれば、関節ごとに点のレイヤー（`joint:<関節>`）が部位の上に出ます。点を動かして書き戻すと、動かした関節だけが `joints-drawn.json` に書かれます（下の「関節（決めたこと）」）。

heosterra の部位のフォルダには 2 つの形があり、道具はフォルダを見て自動で見分けます（下の「部位のフォルダの 2 つの形」）。いまの heosterra（2026-11-25 から）は **1 枚の形**です。

| 形 | 見分け方 | レイヤーの中身 | 書き戻し |
| --- | --- | --- | --- |
| **1 枚**（いまの heosterra） | `.hidden.png` が 1 つも無い | `<部位>.png` そのまま | レイヤーをそのまま `<部位>.png` に書く。`map.png` と `.hidden.png` は書かない |
| 2 枚（前の形） | `.hidden.png` がある | `<部位>.hidden.png` の上に `<部位>.png` を重ねたもの | 重ねた見た目から、見えている所と隠れた所に分け直す |

中身は 1 枚の LibreSprite のスクリプト [`parts-editor.js`](parts-editor.js) と、fs の口の無い版のための補助の CLI [`cli/parts-ase.mjs`](cli/parts-ase.mjs) です。どちらも依存はありません（CLI は Node 22 以上）。

## どの LibreSprite で使うか

LibreSprite のスクリプトからファイルを読み書きする口（`fs`）は、2026-10-12 に LibreSprite の master に入りました。いま配布されている最新の版 **1.3（2026-10-02）には入っていません**。そのため、使う LibreSprite によって手順が 2 つに分かれます。

| LibreSprite | 読み込み | 直す | 書き戻し |
| --- | --- | --- | --- |
| **fs の口のある版**（master の 2026-10-12 以降の組み立て。次の配布版から） | スクリプトの窓の **Load** | LibreSprite | スクリプトの窓の **Save to parts** |
| **1.3**（いまの配布版） | CLI の `open` で `.ase` を作って開く | LibreSprite | `.ase` に保存して CLI の `save` |

どちらの手順でも、レイヤーの並び・名前・ガイド・書き戻しの決まりは同じです（同じ `parts-editor.js` の中身を使います）。fs の口のある版で、CLI が作った `.ase` を開いて窓の **Save to parts** で書き戻すこともできます。

fs の口のある版は、いまは配布されていません。LibreSprite をソースから組むか、LibreSprite の GitHub Actions の master の組み立ての成果物（GitHub にログインが要ります）を使います。このリポジトリで確かめに使ったのは、Linux の組み立て（2026-11-16、`efdbb28`）の成果物です。

## 入れ方

1. [`parts-editor.js`](parts-editor.js) を、LibreSprite の設定フォルダの `scripts` に置きます。

   | OS | 置き場 |
   | --- | --- |
   | Linux | `~/.config/libresprite/scripts/`（`XDG_CONFIG_HOME` があれば `$XDG_CONFIG_HOME/libresprite/scripts/`） |
   | Windows | `%APPDATA%\LibreSprite\scripts\`（ポータブル版は実行ファイルの隣の `scripts\`） |
   | macOS | `~/Library/Application Support/LibreSprite/scripts/` |

2. LibreSprite を開き直すと、メニューの **Scripts** に `parts-editor` が出ます。
3. fs の口のある版では、初めて走らせたときに権限の確認が出ます。**fs.read と fs.write を許してください**（部位のフォルダを読み、PNG を書き戻すのに使います）。1.3 では確認は出ません。
4. 1.3 で使うときは、CLI も使える場所に置きます（このリポジトリを clone するか、`cli/` と `lib/` と `parts-editor.js` を同じ形で置く）。Node 22 以上が要ります。

## 使い方（fs の口のある版）

1. メニューの **Scripts → parts-editor** で窓を開きます。
2. **Parts folder** に、部位のフォルダのパスを入れます（絶対パス。前後の引用符は外します）。前に使ったパスは覚えています。
3. **Load** を押すと、新しい絵ができ、部位ごとに 1 枚のレイヤーが並びます。
4. ガイドを見ながら、部位のレイヤー（部位の名前のレイヤー）を直します。手前の部位に隠れた所を直したいときは、手前の部位のレイヤーの目のしるしを切って隠してください。
5. **Save to parts** を押すと、そのとき前に出ている絵のレイヤーから、部位のフォルダの PNG へ書き戻します。窓の下に、書いたファイルと変わった画素の数が出ます（1 枚の形では見えている所の中で変わった数、2 枚の形では見えている所 ↔ 隠れた所へ移った数も）。

窓の文字は英語です（LibreSprite の画面の字体に日本語の字形が無く、日本語は □ になるため）。

| 窓の部品 | すること |
| --- | --- |
| Parts folder | 部位のフォルダのパス |
| Load | 読み込む（新しい絵を作る） |
| Save to parts | 前に出ている絵から、部位の PNG へ書き戻す |
| Guides | ガイドのレイヤー（`guide:<部位>`）を全部、表示 ↔ 非表示 |
| Map | `map` のレイヤーを表示 ↔ 非表示 |
| Joints | 関節のレイヤー（`joint:<関節>`）を全部、表示 ↔ 非表示 |

前の版にあった **Hidden** のボタンは無くしました（隠れた所は部位のレイヤーに入ったため）。

1 つの部位のガイドだけを見たいときは、LibreSprite のレイヤーの欄で、そのレイヤーの目のしるしを切り替えてください。`map` は部位のレイヤーの下にあるので、出しても部位の絵に隠れます。見るときは部位のレイヤーを隠してください。

読み込んだ絵は、LibreSprite の上では名前の無い新しい絵です。途中で作業を残したいときは、`.ase` に保存してかまいません。あとで開き直して **Save to parts** を押せば、部位へ書き戻せます（レイヤーの名前で部位を引くため）。

## 使い方（1.3）

```sh
# 1. 部位のフォルダから .ase を作る（既定の置き場はフォルダの隣: s-parts → s-parts.ase）
node cli/parts-ase.mjs open path/to/a-pose/s-parts

# 2. LibreSprite 1.3 で s-parts.ase を開いて直し、.ase のまま保存する（Ctrl+S）
#    Scripts → parts-editor の窓の Guides / Map で、表示を切り替えられます

# 3. 部位へ書き戻す（.ase の名前から、隣の同じ名前のフォルダへ書く）
node cli/parts-ase.mjs save path/to/a-pose/s-parts.ase
#    書く前に見るだけなら --dry-run。フォルダを指すなら --dir <部位のフォルダ>
```

| CLI | すること |
| --- | --- |
| `open <部位のフォルダ> [--out <file.ase>]` | 部位ごとに 1 枚のレイヤーにした `.ase` を作る。フォルダの形（1 枚・2 枚）を出す |
| `save <file.ase> [--dir <部位のフォルダ>] [--dry-run] [--no-map]` | `.ase` から部位の PNG へ書き戻す（画素の変わったファイルだけ）。フォルダの形と、ファイルごとに変わる画素の数を出す。1 枚の形では見えている所（`map.png`）の中で変わった数、2 枚の形では見えている所 ↔ 隠れた所へ移った数も出す。`--no-map` は 2 枚の形だけに効く（1 枚の形は `map.png` をいつも書かない） |
| `check <部位のフォルダ>` | 読み込み → `.ase` → 書き戻しの往復で、どのファイルも変わらないことを確かめる（何も書かない）。変わるファイルがあれば、ファイルごとの画素の数を出して 1 で終わる |

### 前の形の `.ase` を持っているとき

前の版の `open` が作った `.ase`（部位ごとに `<部位>` と `<部位>.hidden` の 2 枚のレイヤーがある形）も、そのまま `save` できます。読むときに、`<部位>` を `<部位>.hidden` の上に重ねて 1 枚に寄せ、「old layout: merged …」と知らせます。新しい並び（部位 1 枚・ガイドが一番下）で直したいときは、`.ase` を `save` してから、`open` で作り直してください。窓の **Save to parts** でも同じように寄せて読みます。

`.ase` は heosterra の作業ツリーの中（フォルダの隣）にできます。heosterra に入れないファイルです（heosterra の `.gitignore` に `docs/art/canon/character/**/*-parts.ase` を入れました）。`--out` で別の場所に置いたときは、`save` に `--dir` を付けてください。

**`open` は、同じ場所の `.ase` を確かめずに上書きします。** 直しの残っている `.ase` があるときは、先に `save` してから `open` してください。

### 前の道具（0.2 まで）で、1 枚の形のフォルダを `save` してしまったとき

0.2 までの道具は 1 枚の形を知らず、`.hidden.png` の無いフォルダでも 2 枚の形として書き戻していました。そのため `save` すると、部位の絵が重なる所で奥の部位の `<部位>.png` から画素が抜かれ、`<部位>.hidden.png` が作られ、`map.png` も書き換わります（heosterra の `s-parts` を 0.2 で `check` すると、13 部位で延べ 178 画素が抜かれ、`map.png` が 3 画素変わりました）。

そのあとに `open` し直した `.ase` は、部位のレイヤーが「抜かれた `<部位>.png` と作られた `.hidden.png` を重ねたもの」なので、元の 1 枚の絵に戻っています（手直しもそこに入っています）。次の手順で、手直しを失わずに 1 枚の形へ戻せます。

```sh
# 0. この道具を 0.3 以上にする（git pull）
# 1. 部位のフォルダを、最後のコミットの形へ戻す（<部位>.png と map.png。.ase はフォルダの外なので戻らない）
git restore -- docs/art/canon/character/girl/a-pose/s-parts
# 2. 作られた .hidden.png を消す（git に入っていないファイル。消す前に一覧で確かめる）
git ls-files --others -- 'docs/art/canon/character/girl/a-pose/s-parts/*.hidden.png'
rm docs/art/canon/character/girl/a-pose/s-parts/*.hidden.png
# 3. 手直しの入った .ase を書き戻す（「部位のフォルダの形: 1 枚」と出て、直した部位だけが出ること）
node cli/parts-ase.mjs save docs/art/canon/character/girl/a-pose/s-parts.ase --dry-run
node cli/parts-ase.mjs save docs/art/canon/character/girl/a-pose/s-parts.ase
```

- 2 を飛ばすと、フォルダは 2 枚の形と見なされ、また分け直されます。**`save` の前に `.hidden.png` を消してください。**
- 汚れた形をすでにコミットしてしまったときは、1 で `git restore --source=<汚れる前のコミット> -- <部位のフォルダ>` にします。
- 2026-11-26 に、heosterra の `s-parts` と `se-parts` の写しで確かめました: 0.2 で `open` → `save`（汚れる）→ `open` し直し → LibreSprite 1.3 で胴の描き足しと頭の見えている所を 1 画素ずつ直して保存 → 上の 1〜3。`git status` に出るのは直した 2 つの `<部位>.png` だけで、画素は元の 1 枚に直した画素を足したもの、`.hidden.png` は無く、`map.png` は元のまま。

## heosterra の部位のフォルダ（調べたこと）

heosterra の `docs/art/canon/character/girl/a-pose/` に、少女の A ポーズの 5 方向（`e` `n` `ne` `s` `se`）の `〇〇-parts` があります。作っているのは heosterra の `docs/art/canon/character/scripts/model-parts.ts`（`split` と `fill`）です。

### 部位のフォルダの 2 つの形

heosterra は 2026-11-25（コミット `ee4e88d3f`「部位の絵を 1 枚にまとめる」）に、部位の絵を 2 枚から 1 枚にしました。道具は、フォルダに `.hidden.png` が 1 つでもあれば 2 枚の形、1 つも無ければ 1 枚の形として扱います。

| ファイル | 1 枚の形（いま） | 2 枚の形（前） |
| --- | --- | --- |
| `<部位>.png` | 部位の絵 1 枚。**見えている所**（立ち絵の画素のまま）と、それ以外の**隠れた所の下書き・描き足し**（`split`・`fill`・手直し）が同じ 1 枚に入っている | その部位の**見えている所**だけ |
| `<部位>.hidden.png` | 無い | その部位の**隠れた所の下書き** |
| `map.png` | **見えている所の印**。部位の色のマスが、その部位の見えている所。絵のあるマスとぴったり同じ | 部位の見分けの地図（見えている所と同じ分け方） |
| `parts.json` | `grid`（絵の大きさ）、`joints`（3D の骨の関節の位置）、`parts`（部位ごとの `root`・`tip` の関節、親、画素の数）、`order`（重ねる順。**奥 → 手前**） | 同じ |
| `../<方向>.png` | 立ち絵（部位に分ける前の絵） | 同じ |

- PNG はどれも `grid`×`grid`（いまは 128×128）の全面の絵で、置く位置は (0, 0)、半透明の画素はありません。
- 部位の名前は 14（`torso` `head` `upper-arm-l` `forearm-l` `hand-l` `upper-arm-r` `forearm-r` `hand-r` `thigh-l` `shin-l` `foot-l` `thigh-r` `shin-r` `foot-r`）。
- 1 枚の形で `map.png` のマスを部位に読むときは、heosterra の `labelsFromMap` と同じく、いちばん近い `PART_COLORS` の部位にします。こうして読んだ見えている所を集めた絵は、5 方向とも立ち絵と画素まで同じです（2026-11-26 に確かめました）。heosterra はこの一致を試験（`packages/art-check/src/model-parts.test.ts`）で縛っています。
- 1 枚の形を `order` の順に重ねた絵（読み込んだ直後の見た目）は、立ち絵と少しだけ違います: `e` 5・`n` 0・`ne` 13・`s` 3・`se` 2 画素。手前の部位の描き足しが、奥の部位の見えている所に被る所です（`order` は部位ごとの 1 つの順で、画素ごとの奥・手前とは限らないため）。
- `parts.json` の `hidden`（隠れた所の画素の数）は `split` の時点の数です。道具は `parts.json` を書き換えません。

## レイヤーの並び（決めたこと）

下（奥）から上（手前）へ:

| レイヤー | 中身 | 最初の表示 | 編集 |
| --- | --- | --- | --- |
| `map` | `map.png` | 隠す | 鍵 |
| `guide:<部位>` | 部位ごとのガイド（`order` の順にくり返す） | 出す | 鍵 |
| `<部位>` | 1 枚の形: `<部位>.png` そのまま。2 枚の形: `<部位>.hidden.png` の上に `<部位>.png` を重ねたもの（見えている所が優先）。`order` の順（奥 → 手前）にくり返す | 出す | できる |
| `joint:<関節>` | 絵の上の関節の点（`joints-drawn.json` があるときだけ。その並びの順） | 出す | できる |

- 部位は 1 枚のレイヤーにしました。部位を、見えている所と隠れた所を合わせた 1 つの絵として直せるようにするためです。前の版の `<部位>.hidden` のレイヤーはありません。
- 読み込んだ直後の見た目は、全部の部位を重ねた絵です。隠れた所の下書きが立ち絵の外へはみ出している所（2 枚の形の `se` など）や、手前の部位の描き足しが奥の部位の見えている所に被る所（1 枚の形で数画素）は、そのまま見えます。
- `map` とガイドは一番下に置きました。ガイドが部位の絵に被らず、直すときに絵が見やすいようにするためです。
- レイヤーの名前はファイルの名前と同じにしました（`head` ↔ `head.png` と `head.hidden.png`）。書き戻しはレイヤーの名前で部位を引くので、**部位のレイヤーの名前は変えないでください**。名前の見つからない部位は書かずに知らせます。
- 書き戻しで奥・手前を決めるのは `parts.json` の `order` で、LibreSprite の上のレイヤーの並びではありません。**部位のレイヤーの並べ替えはしないでください**（並べ替えると、見た目と書き戻した結果が合わなくなります）。
- `map` とガイドは鍵をかけています（うっかり描かないため）。書き戻しには使いません。

## ガイド（決めたこと）

- 部位ごとに、**見えている所と隠れた所を合わせた形の、1 画素外側の輪**を引きます。ガイドは部位のレイヤーの下にあるので、形の内側の縁に引くと部位の画素に全部隠れてしまうためです。外側の輪は、立ち絵の外の何も無い所と、直して部位の画素を消した所で見えます。部位をガイドの外へ描き足すと、ガイドはその下に隠れます。
- 色は `map.png` のその部位の色（読めないときは heosterra の `model-parts.ts` の `PART_COLORS`、それも無い名前は部位ごとにずらした色）。1 枚の形では、名前の分かる部位は `PART_COLORS` を使います（部位の絵が隠れた所も含むので、`map.png` の色の多数決だと見えている所の少ない部位が手前の部位の色を取るため）。
- 輪の画素が見えている所に接していれば **線**、隠れた所（ほかの部位の下）にだけ接していれば **1 つおきの点**。1 枚の形では、見えている所は `map.png` でその部位の色のマス、それ以外の部位の画素が隠れた所です。
- `parts.json` のその部位の `root` と `tip` の関節に、不透明な 1 画素の **点**。関節は部位の内側にあるので、部位のレイヤーを隠すと見えます。
- 線と点は不透明度 170/255 です（レイヤーの不透明度は、スクリプトの口からは変えられないため、画素の不透明度で付けています）。
- ガイドは読み込んだ時点の部位の形で作り、直しても描き直しません（直す前の形の目安として見るため）。
- ほかの部位の輪は、手前・奥にかかわらず、部位の絵に隠れます。1 つの部位の形を全部見たいときは、ほかの部位のレイヤーを隠してください。

## 関節（決めたこと）

heosterra の `animate` は、部位のフォルダの `joints-drawn.json`（`{ "<関節>": { "x": …, "y": … } }`。絵の上の関節の位置）を使って部位を回します。この道具は、それを LibreSprite の上で動かせるようにします。`parts.json` の `joints`（3D の骨を絵に写した位置。ガイドの点）は 3D から決まる値なので、道具は書き換えません。

- `joints-drawn.json` があれば、関節ごとに 1 枚のレイヤー `joint:<関節>` を、部位のレイヤーの上（一番手前）に作ります。関節が重なっても見分けられるように、1 枚に 1 つの関節です。
- 点は、値を四捨五入した画素（heosterra と同じ）に不透明な 1 画素。上下左右の 4 画素に、見つけやすくするための薄い印（不透明度 110/255）を付けます。色は、その関節を `root` に持つ部位の色（無ければ白）。
- 動かし方: そのレイヤーを選んで、移動の道具でレイヤーごと動かすか、新しい位置に鉛筆で不透明な点を打ちます（元の点は消しても、消し忘れてもかまいません）。
- 書き戻しは、レイヤーの**不透明な画素**だけを読みます（薄い印は読みません）。
  - 不透明な画素が、読み込んだときの位置だけ → 動いていない。値はそのまま（小数も残す）
  - それ以外の不透明な画素がちょうど 1 つ → そこへ動いた。値は画素の位置（整数）
  - それ以外が 2 つ以上、不透明な画素が無い、レイヤーが無い → その関節は書かずに知らせる
- 動いた関節があるときだけ `joints-drawn.json` を書きます。キーの並びと、動いていない関節の値はそのままです（2 字下げの JSON。heosterra の prettier に合う形）。
- `joints-drawn.json` の無いフォルダでは、関節のレイヤーは作りません。
- 2026-11-26 に、heosterra の `s-parts` の写しで確かめました: CLI の `open` → LibreSprite 1.3（headless）で開いて `joint:LeftForeArm` の点を動かして `.ase` に保存 → `save`。変わったのは `joints-drawn.json` の `LeftForeArm` だけ。5 方向とも `check` で往復して変わるファイルはありませんでした。

## 書き戻し（決めたこと）

### 1 枚の形（いまの heosterra）

- 部位のレイヤーを、**分け直さずにそのまま** `<部位>.png` に書きます。**画素の変わったファイルだけ**を書き、画素が同じなら PNG のバイト列も変えません。
- `.hidden.png` は作りません。`map.png` は書き換えません（見えている所の印は heosterra の `split --map` で決めるもので、この道具では変えない）。
- 見えている所（`map.png` でその部位の色のマス）の画素を変えたときは、その数を出して知らせます（`… px changed in visible cells (map.png) …`）。heosterra では、見えている所を集めた絵が立ち絵 `<方向>.png` と全画素一致することを試験で縛っているので、そのまま入れると heosterra の試験が落ちます。見えている所を直したいときは、heosterra の HOWTO (B) のとおり立ち絵を直して `split --map` をやり直してください。
- 読み込んで何も直さずに書き戻すと、5 方向とも、どのファイルも変わりません（`check` で確かめました）。
- レイヤーの見つからない部位は書かずに知らせます。前の形の `.ase`（`<部位>.hidden` のレイヤーのある形）は 1 枚に寄せて読みます。

### 2 枚の形（前の形）

- 重ねた見た目から分け直します。画素ごとに、その画素を持っている部位（不透明度が 0 でない部位）のうち、**一番手前（`order` の後ろ）の部位の見えている所**、それより奥の部位の同じ画素は、**その部位の隠れた所**にします。したがって、書き戻したあとの `<部位>.png` を全部合わせると、エディタで見えている絵と画素まで同じになります。
- 書くのは `<部位>.png` と `<部位>.hidden.png`（レイヤーの名前で引く）と `map.png`。**画素の変わったファイルだけ**を書きます。画素が同じなら、PNG のバイト列も変えません。
- 画素の比べ方: 大きさ・位置・不透明度・色。完全に透明な画素の色は問いません。書くときは、透明な画素の色を 0 に揃えます。
- 読み込んで何も直さずに書き戻すと、`e` `n` `ne` `s` ではどのファイルも変わりません。`se` では、はみ出した下書きの分け直しで、下の数の画素が動きます。
- レイヤーの見つからない部位は、今のファイルの絵を代わりに使って奥・手前を決め、その部位のファイルは書きません。
- `map.png` は、分け直した見えている所から作り直し、変わったときだけ書きます。部位の間で画素を移したとき、`split --map` で分け直しても直した分け方が残るようにするためです（CLI では `--no-map` で書かないようにできます）。

#### 2 枚の形の `se` で、直さずに書き戻したときに動く画素（2026-11-26 に、2 枚の形だったころの `se` で `check` で数えたもの）

`se` では 28 の部位のファイルと `map.png` の 29 ファイルが変わります。見えている所 → 隠れた所へ移る画素が延べ 70、隠れた所 → 見えている所へ移る画素が延べ 89、`map.png` で色の変わる画素が 89 です。はみ出した下書きが見えている所になる分と、手前の部位の下書きの下に入った奥の部位の画素が隠れた所になる分です。

### どちらの形でも

- `parts.json` は **読むだけで書き換えません**。中の画素の数（`pixels`・`hidden`）は、上のとおりもともと PNG と揃っていないので、数え直すと直していないのに json が変わってしまうためです。
- 書く PNG は RGBA 8bit・フィルタなし。圧縮は、このスクリプトの中の deflate（固定ハフマン + LZ77）です。

## LibreSprite のスクリプトの口（調べたこと）と、足りない所を埋めた手

LibreSprite のソースの `src/app/script/api`（master と v1.3）と、同梱のスクリプト（`data/scripts`）を読んで決めました。

| したいこと | fs の口のある版（master） | 1.3 | このスクリプトでの手 |
| --- | --- | --- | --- |
| フォルダの一覧・json・PNG を読む | `fs.listDir` / `fs.readFile`（`///permission fs.read` が要る） | **無い**（`storage` は設定フォルダの中だけ） | master は `fs`。1.3 は CLI |
| PNG のバイト列を画素にする | 口が無い（`app.open` で開くことはできる） | 同じ | スクリプトの中に PNG の読み手（inflate）を持つ |
| 新しい絵 | `command.NewFile({width, height, "color-mode", background})` | 同じ | `NewFile` |
| レイヤーを足す | `command.NewLayer({name, top})`（`Sprite` に足す口は無い） | `command.NewLayer` はある | `NewLayer` |
| レイヤーに画素を置く | `layer.createCel(frame)` → `cel.image.putImageData(RGBA)` | **`createCel` が無い**（空のレイヤーに cel を作れない） | master は `createCel`。1.3 は CLI が `.ase` を組む |
| レイヤーの表示・鍵 | `layer.isVisible` / `layer.isEditable` | 同じ | 読み込み後に決め、窓のボタンで切り替え |
| レイヤーの画素を読む | `layer.cel(0)` の `image.getImageData()` と `cel.x` / `cel.y`（cel は詰められて位置がずれることがある） | 同じ | 絵の大きさに戻してから比べる |
| PNG を書く | `fs.writeFile(path, Uint8Array)`（`///permission fs.write`） | **無い**（`sprite.saveAs` は絵全体を書くだけ） | master はスクリプトの中の PNG の書き手 + `fs.writeFile`。1.3 は CLI |
| 窓 | `app.createDialog(id)`、`addEntry` / `addButton` / `addLabel`、`onEvent` | `app.createDialog()`（id を取らない） | 両方で動く書き方にした |

- 1.3 には `app.isHeadless` も無く、headless（`-b`）で `app.redraw()` を呼ぶと止まります。このスクリプトは、窓のあるときだけ描き直します。
- 1.3 の補助の CLI に Node を選んだのは、heosterra の道具も Node で、依存なしで zlib が使えるためです。CLI が組む `.ase` は 1 コマ・RGBA・レイヤーごとに絵の大きさの cel 1 つで、LibreSprite の `docs/files/ase.txt` に従います。LibreSprite が保存した `.ase` の、詰めて位置のずれた cel も読めます。

## 確かめたこと

### 自動の試験（`npm test`）

heosterra の絵は private のリポジトリのものなので、このリポジトリには入れていません。試験は、同じ形の小さな合成の部位のフォルダ（`test/fixture.mjs`）で行います。

- PNG の読み書きと inflate / deflate を、Node の zlib と比べる（無圧縮・固定・動的ハフマン、フィルタ 0〜4、RGBA / RGB / グレー / パレット）
- 読み込んだ直後のレイヤーの名前・並び・表示・鍵、部位のレイヤーが見えている所と隠れた所を重ねたものであること、合成が立ち絵と同じこと
- ガイドの線・点線・関節の点。ガイドが部位の絵に被らず、読み込んだ直後の見た目でも見えること
- 直さずに書き戻すと何も書かないこと
- 1 画素直すと、その部位の PNG だけが書き換わり、直した 1 画素のほかは大きさ・位置・透明まで同じで、ほかのファイルはバイト列まで同じこと
- 手前の部位に隠れた所を直したとき（`<部位>.hidden.png` だけ）、手前の部位の画素を消したとき（奥の部位の隠れた所が見えている所へ移り、書き戻したあとの見えている所を全部合わせるとエディタの見た目と同じ）、画素を部位の間で移したとき（`map.png` も変わる）、レイヤーが消えたとき
- 隠れた所の下書きが立ち絵の外へはみ出している形（`se` のような形）: 読み込んだ直後の見た目に出ること、直さずに書き戻すと動くファイルと画素の数、一度書き戻したあとは往復で変わらないこと
- 前の形の `.ase`（`<部位>.hidden` のレイヤーのある形）を 1 枚に寄せて読むこと
- LibreSprite が詰めた cel（位置のずれた小さい cel）を読めること
- CLI の `open` / `save` / `check`
- 1 枚の形（`test/one.test.mjs`）: 形の見分け、部位のレイヤーが `<部位>.png` そのままであること、直さずに書き戻すと何も書かないこと、隠れた所を直すと `<部位>.png` だけを書き（分け直さない・`.hidden.png` も `map.png` も書かない）、見えている所を直すと数えて知らせること、ガイド、レイヤーの無い部位、前の形の `.ase`、前の道具に分けられたフォルダから開いた `.ase` を戻したフォルダへ書き戻すと直した部位だけが変わること

### 本物の LibreSprite での確かめ（`test/libresprite/run.mjs`）

LibreSprite を headless（`-b --script`）で走らせて、往復を確かめる手順です。部位のフォルダは作業のフォルダへ写してから使い、元のフォルダは書き換えません。

```sh
node test/libresprite/run.mjs --libresprite <LibreSprite の実行ファイル> --parts <部位のフォルダ> [--mode ase|inapp|both] [--edit-layer head]
```

- `--mode ase`（1.3 の道）: CLI の `open` → 直さずに CLI の `save`（はみ出しの無い方向では何も書かないこと、ある方向では見込みのファイルだけを書くこと）→ LibreSprite で `.ase` を開き、レイヤーの名前・並び・表示・鍵を確かめ、ガイドを隠した合成を PNG に書き出して、部位を重ねた見込みの絵と比べる（はみ出しの無い方向では立ち絵とも比べる）→ 1 画素直して `.ase` に保存 → CLI の `save` → 直した部位の PNG だけが変わり、直した 1 画素のほかは同じで、ほかのファイルはバイト列まで同じこと。書き戻した PNG を LibreSprite で開いて同じ画素になること。
- `--mode inapp`（fs の口のある版の道）: `parts-editor.js` そのものを LibreSprite の中で走らせ、**Load** と **Save to parts** と同じ処理を通す。fs だけは記憶の中の模擬に差し替えます（下の「確かめられなかったこと」）。

2026-11-26 に、heosterra の少女の A ポーズの 5 方向（`e` `n` `ne` `s` `se`）を写したもので、次の 2 つの LibreSprite について、上の確かめがすべて通りました（部位 1 枚の形で確かめ直したもの）。

| LibreSprite | 道 |
| --- | --- |
| 1.3（配布版の Linux AppImage） | `ase` |

## 確かめられなかったこと

- **画面のある LibreSprite で、人が窓を操作して使うこと**は確かめていません。確かめたのは headless（`-b`）で、窓のボタンの代わりに同じ関数を呼んだところまでです（窓の見た目は master の headless で撮った画面だけ）。
- **本物の `fs` の口で読み書きすること**は確かめていません。headless の LibreSprite は、スクリプトの権限を確認なしに自動で与えるため、その形での実行は控えました。`fs` の口の形（`listDir` / `readFile` の `encoding: "binary"` / `writeFile` に `Uint8Array`）は LibreSprite のソースから読み、確かめでは同じ形の記憶の中の模擬を使っています。初めて走らせたときの権限の確認の窓も見ていません。
- 1.3 の画面のある版での窓の見た目、Windows と macOS での動き、日本語を含むパスは確かめていません。
- 1.3 で `.ase` を開いたまま、レイヤーの並べ替えやグループ化をした場合は試していません（1.3 は `.ase` のグループを読み込みで平らにします。書き戻しはレイヤーの名前で部位を引き、奥・手前は `parts.json` の `order` で決めるので、並べ替えると見た目と書き戻した結果が合わなくなります）。
- ガイドを一番下に置いたときの、画面のある LibreSprite での見やすさは、人の目では確かめていません（確かめたのは、表示中のレイヤーを重ねた絵を Node で描いたところまで）。
